API REST & WebSocket

Référence des points d’entrée REST et du protocole WebSocket Lavalink v4.

Vue d’ensemble

RavaLink vise le contrat HTTP REST et WebSocket de Lavalink v4 afin de fonctionner avec les clients compatibles Lavalink. Le port par défaut est 2333. Les routes protégées utilisent l’en-tête Authorization avec le mot de passe configuré sur le nœud.

Authorization: VOTRE_MOT_DE_PASSE
User-Id: ID_NUMERIQUE_DU_BOT
Client-Name: mon-client/1.0.0
Compatibilité : la présence d’une route ou d’un champ dans la référence Lavalink ne garantit pas à elle seule que chaque cas limite est implémenté. Consultez le registre de compatibilité et les tests associés à la release.

REST — routes principales

RouteUsage
GET /versionInformations de version du nœud.
GET /v4/infoInformations et capacités du nœud.
GET /v4/statsStatistiques globales du serveur.
GET /v4/loadtracks?identifier=…Résolution d’un identifiant, URL ou préfixe de recherche.
GET /v4/decodetrack?encodedTrack=…Décodage des métadonnées d’une piste.
POST /v4/decodetracksDécodage d’une liste de pistes.
GET /v4/sessions/{sessionId}/playersListe des lecteurs d’une session.
PATCH /v4/sessions/{sessionId}/players/{guildId}Créer ou mettre à jour un lecteur.
DELETE /v4/sessions/{sessionId}/players/{guildId}Supprimer un lecteur.
PATCH /v4/sessions/{sessionId}Mettre à jour les paramètres de session, dont le resuming.

La gestion d’un lecteur couvre notamment la piste, le volume, la pause, la position et les filtres lorsque ceux-ci sont pris en charge. Les payloads exacts, paramètres query et codes d’erreur sont décrits dans la spécification REST liée ci-dessous.

WebSocket

Ouvrez une connexion WebSocket sur /v4/websocket. Fournissez Authorization, User-Id et Client-Name lors du handshake. Le serveur émet notamment les opérations ready, playerUpdate, stats et event.

  • ready : confirme la connexion et fournit l’identifiant de session.
  • playerUpdate : transmet la position et l’état du lecteur.
  • stats : transmet les statistiques du nœud.
  • event : signale les événements de piste et de voix.

Exemple de vérification

curl -i -H "Authorization: VOTRE_MOT_DE_PASSE" http://127.0.0.1:2333/version
curl -i -H "Authorization: VOTRE_MOT_DE_PASSE" http://127.0.0.1:2333/v4/info
curl -i -H "Authorization: VOTRE_MOT_DE_PASSE" http://127.0.0.1:2333/v4/stats

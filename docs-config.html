Configuration

Référence des variables d’environnement, paramètres TOML et options du serveur.

Configuration

RavaLink lit par défaut le fichier TOML config/ravalink.toml dans son répertoire de travail. Définissez RAVALINK_CONFIG pour utiliser un autre chemin. Les variables d'environnement ont priorité sur les valeurs du TOML.

Exemple TOML

[server]
address = "0.0.0.0"
port = 2333
password = "replace-with-a-long-random-secret"
player_update_interval = 5

[logging]
level = "info"

[audio]
buffer_duration_ms = 400
frame_buffer_duration_ms = 5000
opus_encoding_quality = 10
resampling_quality = "low"
max_source_download_bytes = 134217728
max_decoded_cache_bytes = 268435456
max_active_decoded_pcm_bytes = 268435456

[metrics]
prometheus_enabled = false
prometheus_endpoint = "/metrics"

La configuration complète et à jour est disponible dans le fichier d'exemple du dépôt. Les paramètres non listés ici peuvent évoluer entre releases ; privilégiez ce fichier comme référence.

YouTube : authentification OAuth

Le lecteur YouTube intégré fonctionne sans compte. Pour les vidéos qui exigent une session, RavaLink peut utiliser le flux OAuth Device Flow du client YouTube TV. L’authentification est facultative et désactivée par défaut.

Aucune configuration Google Cloud à créer : RavaLink embarque les identifiants nécessaires au flux. Vous n’avez besoin ni d’une clé API, ni d’un Client ID, ni d’un Client Secret personnels.

Activer OAuth

Dans config/ravalink.toml, ajoutez :

[youtube.oauth]
enabled = true
token_file = "data/youtube-oauth.json"
skip_initialization = false
# refresh_token = "VOTRE_JETON_DE_RENOUVELLEMENT"

Les mêmes réglages peuvent être définis avec les variables d’environnement :

VariableDéfautDescription
RAVALINK_YOUTUBE_OAUTH_ENABLEDfalseActive OAuth. Passez à true pour démarrer l’autorisation.
RAVALINK_YOUTUBE_OAUTH_REFRESH_TOKENVideJeton de renouvellement existant. Laissez vide pour utiliser le Device Flow.
RAVALINK_YOUTUBE_OAUTH_TOKEN_FILEdata/youtube-oauth.jsonEmplacement où RavaLink conserve les jetons.
RAVALINK_YOUTUBE_OAUTH_SKIP_INITIALIZATIONfalseEmpêche le lancement automatique de l’étape d’initialisation OAuth.

Autoriser le compte Google

  1. Activez OAuth puis démarrez ou redémarrez RavaLink.
  2. Consultez les logs. Lorsqu’aucun jeton valide n’est disponible, RavaLink affiche une adresse d’autorisation et un code à usage unique.
  3. Ouvrez google.com/device sur un téléphone ou un ordinateur.
  4. Saisissez le code affiché dans les logs, connectez-vous au compte Google voulu et confirmez l’accès.
  5. Laissez le serveur démarré pendant l’autorisation. RavaLink récupère le jeton et l’enregistre dans le fichier configuré.
Ne partagez pas le code d’autorisation ni le fichier de jetons. Ils donnent accès à la session associée au compte Google.

Stockage et renouvellement

Le fichier défini par token_file contient les informations nécessaires au renouvellement de la session. Il doit rester accessible en écriture et être conservé entre les redémarrages, mises à jour et recréations de conteneur. Ne le placez pas dans un dépôt Git ni dans un répertoire public.

Si le fichier est supprimé ou si l’accès est révoqué depuis Google, redémarrez RavaLink pour effectuer une nouvelle autorisation. Vous pouvez aussi fournir un jeton de renouvellement existant avec RAVALINK_YOUTUBE_OAUTH_REFRESH_TOKEN.

Dépannage

  • Aucun code n’apparaît : vérifiez que RAVALINK_YOUTUBE_OAUTH_ENABLED=true, consultez les logs du démarrage courant et vérifiez l’accès réseau à Google.
  • Le code a expiré : redémarrez RavaLink et utilisez le nouveau code affiché.
  • Le fichier ne peut pas être écrit : vérifiez son chemin, les droits du processus et la présence du volume persistant.
  • Le jeton ne fonctionne plus : vérifiez qu’il n’a pas été révoqué. Relancez le Device Flow si nécessaire.
  • YouTube renvoie HTTP 403 : OAuth ne débloque pas toutes les vidéos. Certaines restrictions de compte, de région ou de lecture peuvent toujours s’appliquer.

Plugins et fournisseurs

Le répertoire par défaut des extensions est plugins. Vous pouvez le remplacer avec RAVALINK_PLUGINS_DIRECTORY. Les intégrations Spotify et Apple Music peuvent nécessiter les variables RAVALINK_SPOTIFY_CLIENT_ID, RAVALINK_SPOTIFY_CLIENT_SECRET et RAVALINK_APPLE_MUSIC_TOKEN.

Consultez le guide Plugins & intégrations pour l’installation, la création et les limites de sécurité.

Configuration

Référence des variables d’environnement, paramètres TOML et options du serveur.

Configuration

RavaLink lit par défaut le fichier TOML config/ravalink.toml dans son répertoire de travail. Définissez RAVALINK_CONFIG pour utiliser un autre chemin. Les variables d'environnement ont priorité sur les valeurs du TOML.

YouTube : cookies et OAuth Google

Le plugin YouTube intégré peut effectuer des recherches (ytsearch: et ytmsearch:), résoudre des vidéos et charger des playlists. YouTube peut toutefois refuser certains flux aux clients non authentifiés. RavaLink propose deux mécanismes facultatifs : un fichier de cookies de navigateur au format Netscape, ou OAuth Google Device Flow. Ils peuvent améliorer l'accès, mais ne garantissent pas la lecture de toutes les vidéos.

Quelle méthode choisir ?

  • OAuth Device Flow : recommandé pour un serveur sans interface graphique. Vous autorisez une seule fois le compte Google depuis un téléphone ou un ordinateur, avec un code affiché dans les logs du serveur. RavaLink conserve et renouvelle ensuite le jeton.
  • Cookies Netscape : utile si vous disposez déjà d'un export cookies.txt depuis un navigateur connecté à YouTube.

1. Créer un client OAuth Google

  1. Ouvrez la Google Cloud Console et sélectionnez ou créez un projet.
  2. Dans API et services → Bibliothèque, activez YouTube Data API v3 pour ce projet.
  3. Ouvrez Google Auth Platform. Si Google demande de configurer l'écran de consentement, renseignez le nom de l'application et les coordonnées demandées, puis enregistrez.
  4. Dans Clients, créez un nouveau client OAuth.
  5. Choisissez le type d'application TVs and Limited Input devices (téléviseurs et appareils à saisie limitée). Le flux utilisé par RavaLink est le Device Authorization Grant ; un client Web ou Desktop classique n'est pas le type attendu.
  6. Copiez le Client ID. Ne le confondez pas avec le secret d'un client Web : RavaLink attend le Client ID et le Client Secret du client OAuth.

Les menus Google peuvent évoluer. La référence du flux est la documentation Google OAuth pour les appareils à saisie limitée.

2. Définir les paramètres RavaLink

Les trois paramètres OAuth doivent être configurés ensemble. Si un seul est renseigné, le plugin YouTube refuse de démarrer. RavaLink demande le scope Google https://www.googleapis.com/auth/youtube, nécessaire à ses requêtes InnerTube authentifiées.

VariableObligatoireRôle
RAVALINK_YOUTUBE_OAUTH_CLIENT_IDPour OAuthClient ID créé dans Google Cloud Console.
RAVALINK_YOUTUBE_OAUTH_CLIENT_SECRETPour OAuthClient Secret associé au même client Google. À conserver confidentiel.
RAVALINK_YOUTUBE_OAUTH_TOKEN_FILEPour OAuthChemin du fichier privé dans lequel RavaLink enregistre les jetons d'accès et de renouvellement.
RAVALINK_YOUTUBE_COOKIES_FILEAlternativeChemin d'un fichier de cookies exporté au format Netscape.

Exemple pour un conteneur Pelican/Pterodactyl :

RAVALINK_YOUTUBE_OAUTH_CLIENT_ID=123456789-example.apps.googleusercontent.com
RAVALINK_YOUTUBE_OAUTH_CLIENT_SECRET=YOUR_GOOGLE_OAUTH_CLIENT_SECRET
RAVALINK_YOUTUBE_OAUTH_TOKEN_FILE=/home/container/config/youtube-oauth-token.json

Exemple équivalent dans config/ravalink.toml :

[youtube]
oauth_client_id = "123456789-example.apps.googleusercontent.com"
oauth_client_secret = "YOUR_GOOGLE_OAUTH_CLIENT_SECRET"
oauth_token_file = "/home/container/config/youtube-oauth-token.json"

Le répertoire parent du fichier doit être accessible en écriture par l'utilisateur qui exécute RavaLink. Choisissez un emplacement persistant : le fichier doit survivre aux redémarrages et aux remplacements du conteneur. Ne placez jamais ce fichier dans un dépôt Git ou dans un dossier public.

3. Effectuer la première autorisation

  1. Enregistrez les variables ou le fichier TOML, puis démarrez ou redémarrez RavaLink.
  2. Ouvrez les logs du serveur. Au premier démarrage sans jeton valide, RavaLink affiche une ligne contenant l'adresse Google et un code utilisateur, sous la forme [RavaLink YouTube OAuth] Open ... and enter code ....
  3. Depuis un téléphone ou un ordinateur, ouvrez l'adresse affichée dans les logs.
  4. Saisissez le code utilisateur exactement comme affiché, connectez-vous au compte Google voulu et confirmez l'autorisation.
  5. Laissez RavaLink démarré pendant l'autorisation. Il interroge Google périodiquement jusqu'à ce que l'autorisation soit acceptée ou que le code expire.
  6. Après validation, RavaLink enregistre le jeton dans le fichier configuré et poursuit son initialisation.
Important : l'URL et le code sont générés par Google et changent à chaque tentative. Ne réutilisez pas un ancien code et ne publiez pas une capture des logs qui le contient.

4. Renouvellement et persistance

Le fichier de jeton contient un jeton d'accès et un jeton de renouvellement. RavaLink utilise le jeton d'accès pour ses requêtes YouTube, renouvelle automatiquement l'accès avant son expiration et remplace le fichier de manière sécurisée. Sur les systèmes Unix, le fichier est créé avec des permissions privées (0600).

Conservez le fichier entre les redémarrages. Si vous le supprimez ou si le jeton de renouvellement est révoqué, redémarrez RavaLink : un nouveau code d'autorisation sera affiché. Le Client ID doit rester identique à celui qui a servi à obtenir le jeton.

5. Utiliser OAuth avec Pelican ou Pterodactyl

Dans l'onglet Startup de l'egg RavaLink, renseignez le Client ID, le Client Secret et le chemin du fichier de jeton. Si les variables ne sont pas visibles, mettez d'abord à jour l'egg depuis le dépôt officiel, puis actualisez les variables du serveur dans le panel. Pour le chemin, utilisez un emplacement dans le répertoire persistant du serveur, par exemple /home/container/config/youtube-oauth-token.json. Consultez le guide Pelican / Pterodactyl.

6. Dépannage OAuth

  • Les paramètres OAuth sont incomplets : configurez le Client ID, le Client Secret et le chemin du jeton ensemble, ou laissez les trois vides pour désactiver OAuth.
  • Le code n'apparaît pas : vérifiez que le Client ID est valide, que le serveur peut joindre oauth2.googleapis.com et que vous consultez les logs du démarrage courant.
  • Le code a expiré : redémarrez RavaLink et utilisez le nouveau code affiché.
  • Google indique que l'accès est refusé : vérifiez le compte choisi et acceptez la demande. Si vous refusez, une nouvelle tentative nécessitera un redémarrage.
  • Impossible de lire ou d'écrire le fichier : vérifiez le chemin, les permissions et l'existence d'un espace de stockage persistant accessible en écriture.
  • Le jeton ne peut pas être renouvelé : vérifiez que le Client ID correspond au client ayant autorisé le compte. Si le jeton a été révoqué, supprimez uniquement l'ancien fichier de jeton puis redémarrez pour recommencer l'autorisation.
  • YouTube renvoie encore HTTP 403 : OAuth ne garantit pas l'accès à tous les flux. Certaines vidéos peuvent exiger d'autres mécanismes de vérification YouTube, notamment un PoToken, ou rester indisponibles pour le compte ou la région.

Cookies YouTube au format Netscape (alternative)

Vous pouvez fournir un export de cookies YouTube au format Netscape via RAVALINK_YOUTUBE_COOKIES_FILE ou [youtube].cookies_file. Le fichier doit être lisible par RavaLink et conservé dans un emplacement privé. Les cookies donnent accès à la session du compte : traitez-les comme un mot de passe, ne les partagez pas et renouvelez-les lorsqu'ils expirent. N'activez pas OAuth uniquement pour utiliser les cookies : ce sont deux méthodes indépendantes et facultatives.

[youtube]
cookies_file = "/home/container/config/youtube-cookies.txt"

Pour utiliser OAuth et les cookies ensemble, renseignez les trois paramètres. Les cookies et OAuth sont alors fournis à l'extracteur YouTube.

Plugins et fournisseurs

Le répertoire par défaut des extensions est plugins. Vous pouvez le remplacer avec RAVALINK_PLUGINS_DIRECTORY. Les intégrations Spotify et Apple Music peuvent nécessiter les variables RAVALINK_SPOTIFY_CLIENT_ID, RAVALINK_SPOTIFY_CLIENT_SECRET et RAVALINK_APPLE_MUSIC_TOKEN.

Consultez le guide Plugins & intégrations pour l’installation, la création et les limites de sécurité.

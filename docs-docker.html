Déploiement avec Docker

Lancez RavaLink dans un conteneur avec Docker Compose ou une construction manuelle.

Déployer l’image officielle GHCR

L’image publiée pour Pelican/Pterodactyl est également utilisable avec Docker directement. Elle contient déjà le binaire RavaLink, vérifié par SHA-256 pendant le build, et fonctionne avec l’utilisateur non-root container. Il n’est pas nécessaire de cloner le dépôt, compiler Rust ou construire une image locale.

Image officielle : ghcr.io/ravalink-project/ravalink:v1.0.0-rc.1. Le tag latest suit la dernière release publiée. Pour les déploiements reproductibles, préférez un tag de version.

Docker Compose (recommandé)

Créez un répertoire de déploiement, puis ajoutez un fichier compose.yml :

services:
  ravalink:
    image: ghcr.io/ravalink-project/ravalink:v1.0.0-rc.1
    container_name: ravalink
    restart: unless-stopped
    init: true
    environment:
      STARTUP: "ravalink"
      RAVALINK_ADDRESS: "0.0.0.0"
      RAVALINK_PORT: "2333"
      RAVALINK_PASSWORD: "${RAVALINK_PASSWORD}"
      RAVALINK_CONFIG: "/home/container/config/ravalink.toml"
    ports:
      - "127.0.0.1:2333:2333"
    volumes:
      - ./config:/home/container/config:ro
      - ./plugins:/home/container/plugins:ro

Créez les dossiers et le secret. Le fichier TOML doit exister avant le démarrage si RAVALINK_CONFIG est défini :

mkdir -p config plugins
curl -fsSL https://raw.githubusercontent.com/Ravalink-Project/Ravalink/master/config/ravalink.example.toml -o config/ravalink.toml
printf 'RAVALINK_PASSWORD=%s\n' "$(openssl rand -hex 32)" > .env
chmod 600 .env

Placez votre configuration dans config/ravalink.toml. Vous pouvez partir du fichier TOML d’exemple. Démarrez et consultez les logs :

docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f ravalink

Le binding 127.0.0.1:2333:2333 limite l’accès à la machine hôte. Placez un reverse proxy TLS/WSS devant le service ou utilisez un réseau privé pour les clients distants. Ne publiez pas le port sans authentification ni filtrage réseau.

Lancement avec docker run

mkdir -p config plugins
docker run -d --name ravalink --restart unless-stopped --init \
  -e STARTUP=ravalink \
  -e RAVALINK_ADDRESS=0.0.0.0 \
  -e RAVALINK_PORT=2333 \
  -e RAVALINK_PASSWORD="VOTRE_SECRET_LONG_ALEATOIRE" \
  -e RAVALINK_CONFIG=/home/container/config/ravalink.toml \
  -p 127.0.0.1:2333:2333 \
  -v "$PWD/config:/home/container/config:ro" \
  -v "$PWD/plugins:/home/container/plugins:ro" \
  ghcr.io/ravalink-project/ravalink:v1.0.0-rc.1

Mise à jour et retour arrière

Épinglez une version précise dans compose.yml. Pour mettre à jour, changez le tag après avoir consulté les notes de version, puis recréez le conteneur :

docker compose pull
docker compose up -d
docker compose logs --tail=100 ravalink

Pour revenir à la version précédente, restaurez son tag dans le fichier Compose et relancez les mêmes commandes. Les données persistantes et la configuration restent dans les dossiers montés sur l’hôte.

Variables indispensables

  • STARTUP doit être défini pour l’entrypoint de cette image ; utilisez ravalink.
  • RAVALINK_PASSWORD doit être un secret aléatoire d’au moins 16 caractères.
  • RAVALINK_CONFIG doit pointer vers un fichier existant si vous le définissez.
  • RAVALINK_ADDRESS doit écouter sur une interface joignable depuis le conteneur ; 0.0.0.0 est le choix habituel en conteneur.
À ne pas faire : n’utilisez pas build: . pour ce parcours, ne montez pas le socket Docker dans le conteneur et ne supposez pas que le tag latest est immuable.

Déploiement avec Docker

Lancez RavaLink dans un conteneur avec Docker Compose ou une construction manuelle.

2. Déploiement Docker

Le dépôt fournit un Dockerfile multi-stage et un fichier compose.yml. L'image finale contient le binaire Rust et les certificats CA ; le processus tourne avec l'utilisateur non privilégié ravalink.

À savoir : le Compose fourni construit l'image depuis le code présent dans le dépôt (build: .). Le tag local ghcr.io/ravalink-project/ravalink:dev ne signifie pas qu'une image préconstruite de production est publiée sur GHCR.

Docker Compose (recommandé)

Installez Docker Engine et le plugin Docker Compose, puis clonez le dépôt :

git clone https://github.com/Ravalink-Project/Ravalink.git
cd Ravalink
cp config/ravalink.example.toml ravalink.toml

printf 'RAVALINK_PASSWORD=%s\\n' "$(openssl rand -hex 32)" > .env
chmod 600 .env

docker compose up -d --build
docker compose ps
docker compose logs -f ravalink

Le fichier Compose publie par défaut le port du conteneur uniquement sur 127.0.0.1:2333 de l'hôte. La configuration TOML est montée en lecture seule dans le conteneur à /etc/ravalink/ravalink.toml. Les variables d'environnement remplacent les valeurs du fichier.

Pour arrêter le service sans supprimer la configuration :

docker compose down

Pour reconstruire après avoir récupéré une nouvelle version du dépôt :

git pull --ff-only
docker compose up -d --build

Build et lancement manuels

docker build -t ravalink:local .
docker run -d --name ravalink --restart unless-stopped \
  -p 127.0.0.1:2333:2333 \
  -e RAVALINK_PASSWORD="$(openssl rand -hex 32)" \
  -v "$PWD/ravalink.toml:/etc/ravalink/ravalink.toml:ro" \
  ravalink:local

Pour rendre le service accessible à distance, modifiez volontairement le binding réseau et appliquez les règles de pare-feu décrites dans la section Réseau et sécurité. Ne montez pas le socket Docker dans le conteneur RavaLink.

Pelican et Pterodactyl

Déployez RavaLink depuis l’egg officiel, configurez les allocations et gérez les mises à jour.

3. Pelican et Pterodactyl

L'équipe publie un egg compatible avec les deux panels. Il utilise le yolk Debian, installe un script de démarrage, détecte l'architecture et récupère le binaire depuis la dernière GitHub Release publiée.

Dépôt officiel des eggsTélécharger egg-ravalink.json

Importer l'egg

  1. Connectez-vous au panel avec un compte administrateur.
  2. Ouvrez Nests / Eggs (Pelican : la rubrique équivalente de gestion des eggs), puis importez le fichier egg-ravalink.json.
  3. Associez l'egg au Nest de votre choix. Le fichier déclare l'image Docker ghcr.io/pterodactyl/yolks:debian.
  4. Enregistrez l'egg et vérifiez que son script d'installation a été exécuté lors de la création du serveur.

Créer et configurer le serveur

  1. Créez un nouveau serveur et sélectionnez le Nest puis l'egg RavaLink.
  2. Allouez un port TCP au serveur. Le port par défaut de RavaLink est 2333 ; le panel doit transmettre ce port dans RAVALINK_PORT.
  3. Dans les variables de démarrage, remplacez impérativement RAVALINK_PASSWORD par un secret aléatoire d'au moins 16 caractères. La valeur par défaut est volontairement invalide.
  4. Vérifiez l'image Debian, l'allocation et les limites de ressources, puis démarrez le serveur.
  5. Consultez la console : le script indique la release détectée, l'architecture et le résultat de la vérification SHA-256 avant de lancer RavaLink.

Le script configure par défaut l'écoute sur 0.0.0.0 et le port 2333 si les variables ne sont pas définies. Le port alloué dans le panel doit correspondre à RAVALINK_PORT.

Mises à jour et sélection de version

À chaque démarrage, le script consulte l'API GitHub Releases, sélectionne la release publiée la plus récente (les préversions sont incluses, les drafts exclues), télécharge le binaire correspondant à l'architecture et le vérifie avec SHA256SUMS. Si la même version est déjà installée et que son empreinte est valide, le téléchargement est évité.

Important : l'egg suit automatiquement la dernière release publiée. Il ne propose pas de variable de version pour épingler une release. Un redémarrage peut donc installer une nouvelle RC ou une version stable dès qu'elle est publiée. Vérifiez la page Releases avant de redémarrer un serveur critique.

En cas d'indisponibilité de GitHub, de binaire manquant ou de checksum invalide, le script arrête le démarrage au lieu d'exécuter silencieusement un ancien binaire non vérifié.

Pelican et Pterodactyl

Déployez RavaLink depuis l’egg officiel, configurez les allocations et gérez les mises à jour.

3. Pelican et Pterodactyl

L'équipe publie une image Docker native compatible Pelican et Pterodactyl, construite pour AMD64 et ARM64. Elle embarque directement le binaire RavaLink vérifié au moment du build et conserve l'entrypoint officiel du yolk Debian.

Dépôt officiel des eggsTélécharger egg-ravalink.json download
Image native : l’egg utilise désormais ghcr.io/ravalink-project/ravalink:latest. Wings récupère l’image automatiquement au démarrage du serveur. Aucun script d’installation ou de téléchargement du binaire n’est exécuté dans le conteneur.

Importer l'egg

  1. Connectez-vous au panel avec un compte administrateur.
  2. Ouvrez Nests / Eggs (Pelican : la rubrique équivalente de gestion des eggs), puis importez le fichier egg-ravalink.json.
  3. Associez l'egg au Nest de votre choix. Le fichier déclare l'image Docker officielle ghcr.io/ravalink-project/ravalink:latest.
  4. Enregistrez l'egg. Il ne contient volontairement aucun script d'installation : le binaire est déjà intégré à l'image.

Créer et configurer le serveur

  1. Créez un nouveau serveur et sélectionnez le Nest puis l'egg RavaLink.
  2. Allouez un port TCP au serveur. Le port par défaut de RavaLink est 2333 ; le panel doit transmettre ce port dans RAVALINK_PORT.
  3. Dans les variables de démarrage, remplacez impérativement RAVALINK_PASSWORD par un secret aléatoire d'au moins 16 caractères. La valeur par défaut est volontairement invalide.
  4. Vérifiez que l'image ghcr.io/ravalink-project/ravalink:latest est sélectionnée, puis démarrez le serveur. Wings téléchargera l'image depuis GHCR si elle n'est pas déjà présente sur le nœud.
  5. Consultez la console : l'entrypoint du yolk transmet la commande de démarrage directement au binaire RavaLink.

L'image utilise l'utilisateur non-root et le répertoire de travail attendus par Pelican/Pterodactyl. Le port alloué dans le panel doit correspondre à RAVALINK_PORT.

Mises à jour et sélection de version

Chaque GitHub Release publiée déclenche automatiquement un workflow qui construit les images linux/amd64 et linux/arm64. Le workflow publie une image versionnée (par exemple ghcr.io/ravalink-project/ravalink:v1.0.0-rc.1) ainsi que le tag mobile latest. Le binaire est téléchargé et vérifié avec SHA256SUMS pendant la construction de l'image, jamais au démarrage du serveur.

Important : pour rendre l'image téléchargeable par Wings sans identifiants, le package GHCR doit être défini comme Public dans les paramètres du package GitHub. Pour forcer la récupération d'une nouvelle version sur un serveur existant, utilisez la fonction Réinstaller du panel.

Le tag latest suit la dernière release publiée par le workflow. Pour épingler une version, remplacez l'image par son tag versionné dans la configuration de l'egg.

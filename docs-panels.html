Pelican et Pterodactyl

Choisissez le fichier d'egg correspondant à votre panel : Pelican utilise son format natif PLCN_v3, tandis que Pterodactyl conserve le format PTDL_v2.

3. Pelican et Pterodactyl

RavaLink publie une image Docker officielle multi-architecture (Linux AMD64 et ARM64) sur GitHub Container Registry. L’egg utilise directement cette image préconstruite ; le binaire est déjà présent dans le conteneur. Deux exports d’egg distincts sont fournis : PLCN_v3 pour Pelican et PTDL_v2 pour Pterodactyl.

Dépôt officiel des eggsTélécharger l'egg Pelican (PLCN_v3) downloadTélécharger l'egg Pterodactyl (PTDL_v2) download
Important — choisissez le bon format : importez egg-ravalink-pelican.json dans Pelican (format PLCN_v3) et egg-ravalink.json dans Pterodactyl (format PTDL_v2). N'utilisez pas le fichier Pterodactyl dans Pelican.
Image Docker native : les deux eggs utilisent ghcr.io/ravalink-project/ravalink:latest. Wings récupère l'image automatiquement. Le binaire est déjà intégré au conteneur : aucun téléchargement n'est exécuté au démarrage.

Importer le bon egg

Pelican

  1. Téléchargez egg-ravalink-pelican.json au format natif PLCN_v3.
  2. Dans l'administration Pelican, ouvrez la gestion des Eggs et utilisez la fonction d'importation.
  3. Sélectionnez le fichier Pelican, choisissez le Nest de destination puis validez l'import.

Pterodactyl

  1. Téléchargez egg-ravalink.json au format PTDL_v2.
  2. Dans l'administration Pterodactyl, ouvrez Nests / Eggs puis importez le fichier.
  3. Associez l'egg au Nest voulu et enregistrez.

Les deux fichiers décrivent le même service et la même image Docker, mais leurs structures d'export ne sont pas interchangeables. L'egg Pelican utilise startup_commands et des règles de variables sous forme de tableaux ; l'egg Pterodactyl utilise le schéma PTDL_v2.

Créer et configurer le serveur

  1. Créez un nouveau serveur et sélectionnez le Nest puis l'egg RavaLink.
  2. Allouez un port TCP au serveur. Le port par défaut de RavaLink est 2333 ; le panel doit transmettre ce port dans RAVALINK_PORT.
  3. Dans les variables de démarrage, remplacez impérativement RAVALINK_PASSWORD par un secret aléatoire d'au moins 16 caractères. La valeur par défaut est volontairement invalide.
  4. Vérifiez que l'image ghcr.io/ravalink-project/ravalink:latest est sélectionnée, puis démarrez le serveur. Wings téléchargera l'image depuis GHCR si elle n'est pas déjà présente sur le nœud.
  5. Consultez la console : l'entrypoint de l'image transmet la commande de démarrage directement au binaire RavaLink. Aucun script ne télécharge jq ou le binaire au démarrage.

L'image utilise l'utilisateur non-root et le répertoire de travail attendus par Pelican/Pterodactyl. Le port alloué dans le panel doit correspondre à RAVALINK_PORT.

Mises à jour et sélection de version

Les images officielles sont disponibles pour les architectures Linux AMD64 et ARM64. Chaque version publiée possède un tag dédié, ainsi que le tag latest.

Choisir une version : utilisez latest pour suivre la dernière version publiée ou un tag versionné pour conserver une version précise.

Le tag latest suit la dernière release publiée par le workflow. Pour épingler une version, remplacez l'image par son tag versionné dans la configuration de l'egg.

Installer des plugins

Les plugins communautaires se placent dans /home/container/plugins/. Chaque extension dispose de son dossier, d’un manifeste ravalink-plugin.toml et de son exécutable. Après installation ou modification, redémarrez le serveur : la découverte se fait au démarrage.

/home/container/plugins/\n└── community-source/\n    ├── ravalink-plugin.toml\n    └── bin/community-source

Consultez le guide complet des plugins pour le format du manifeste, le protocole JSON et le développement Rust.

Plugins & intégrations

Comprendre les sources intégrées, installer un plugin communautaire et développer sa propre intégration.

Architecture des plugins

RavaLink possède son propre système d’extensions Rust. Ce n’est pas un chargeur de plugins Java : les fichiers .jar conçus pour Lavalink Java ne peuvent pas être chargés directement.

INSTALLATION SIMPLEPlugin externe arrow_outward

Un exécutable indépendant, installé sans recompiler RavaLink.

DÉVELOPPEMENTPlugin Rust natif arrow_outward

Une intégration compilée dans le workspace RavaLink.

Choisissez un plugin externe pour distribuer une source indépendamment du serveur. Choisissez un plugin natif si vous contribuez au cœur du projet ou avez besoin de l’API interne.

Intégrations incluses

IntégrationFonctionIdentifiants courants
YouTubeRecherche, résolution de vidéos et playlists, sélection de source audio.ytsearch:, ytmsearch:, URL YouTube
LavaSrcRésolution des métadonnées Spotify, Apple Music et Deezer, puis correspondance avec une piste audio lisible.URL et URI Spotify / Apple Music / Deezer
LavaSearchRecherche de pistes et découverte structurée d’albums, artistes et playlists.spsearch:, amsearch:, dzsearch:, album:, artist:, playlist:

La disponibilité d’un fournisseur dépend de ses API, de restrictions régionales et de ses identifiants. Le fait qu’une source soit annoncée par le serveur ne garantit pas que toutes ses opérations fonctionnent.

Variables des fournisseurs

RAVALINK_SPOTIFY_CLIENT_ID=...
RAVALINK_SPOTIFY_CLIENT_SECRET=...
RAVALINK_APPLE_MUSIC_TOKEN=...

YouTube peut également utiliser des cookies Netscape ou l’authentification OAuth Device Flow. Voir la référence de configuration YouTube.

Installer un plugin externe

Les plugins externes sont des exécutables autonomes lancés par RavaLink lorsqu’un identifiant correspond à leur préfixe. Le serveur échange une requête et une réponse JSON via stdin/stdout.

1. Préparer le dossier

Le dossier par défaut est plugins/, relatif au répertoire de travail. Il peut être remplacé par RAVALINK_PLUGINS_DIRECTORY.

plugins/
└── community-source/
    ├── ravalink-plugin.toml
    └── bin/
        └── community-source

Le binaire doit correspondre à l’OS, à l’architecture CPU et à l’environnement Linux du serveur. Sur Linux, rendez-le exécutable :

chmod 0755 plugins/community-source/bin/community-source

2. Déclarer le plugin

Créez plugins/community-source/ravalink-plugin.toml :

api_version = 1
name = "community-source"
version = "1.0.0"
description = "Community source integration"
capabilities = ["track", "playlist", "search"]
identifier_prefix = "community:"
program = "bin/community-source"
args = ["--stdio"]

[environment]
API_TOKEN = "inject-at-deployment-time"

[config]
region = "eu"
ChampObligatoireDescription
api_versionNonVersion du protocole, actuellement 1.
name, version, descriptionOuiIdentité et métadonnées du plugin.
capabilitiesNonCapacités descriptives annoncées.
identifier_prefixOuiPréfixe qui route les identifiants vers ce plugin.
programOuiChemin de l’exécutable, relatif au dossier du plugin ou absolu.
argsNonArguments transmis directement au programme.
environmentNonVariables d’environnement explicitement transmises.
configNonConfiguration TOML transmise dans chaque requête JSON.

3. Contrat de requête

Pour un identifiant comme community:some-track, RavaLink démarre le programme, écrit une requête JSON sur stdin puis ferme stdin :

{
  "protocolVersion": 1,
  "identifier": "community:some-track",
  "config": { "region": "eu" }
}

Le plugin doit lire toute la requête, écrire exactement une réponse JSON sur stdout puis quitter. N’écrivez jamais de logs, de barre de progression ou de texte de debug sur stdout. L’environnement du processus est nettoyé : seules les variables déclarées et RAVALINK_PLUGIN_PROTOCOL=1 sont présentes.

4. Réponse attendue

Le plugin retourne soit null s’il ne prend pas en charge l’identifiant, soit un objet PluginLoadResult. Les types de chargement suivent le format Lavalink :

{
  "loadType": "search",
  "data": []
}

Pour un résultat réel, data doit contenir les objets de piste encodés attendus par Lavalink. Une piste doit inclure ses métadonnées et une source HTTP(S) lisible par le moteur audio. Un résultat metadata-only ne suffit pas à démarrer la lecture.

Déclaration directe dans le TOML

Alternative au manifeste : ajoutez une entrée [[plugins]] dans config/ravalink.toml. Dans ce cas, program doit être un chemin absolu. Ne déclarez pas deux fois le même plugin.

[[plugins]]
name = "community-source"
version = "1.0.0"
description = "Community source integration"
capabilities = ["track", "search"]
identifier_prefix = "community:"
program = "/opt/ravalink/plugins/community-source"
args = ["--stdio"]

[plugins.environment]
API_TOKEN = "injected-by-deployment"

[plugins.config]
region = "eu"

Développer un plugin Rust natif

Les plugins natifs sont des crates du workspace qui implémentent le trait RavaLinkPlugin fourni par ravalink-plugin-api.

Responsabilités du trait

  • descriptor() : nom, version, description et capacités annoncées.
  • supports_identifier() : indique si le plugin prend en charge un identifiant ou préfixe.
  • load_tracks() : résout l’identifiant et renvoie un résultat compatible Lavalink, None s’il ne le gère pas, ou une erreur typée.

Le trait est asynchrone et impose Send + Sync. Le registre applique un délai maximal de résolution de 30 secondes.

Créer le crate

Ajoutez un crate sous crates/plugins/, puis déclarez-le dans les membres du workspace dans le Cargo.toml racine.

[dependencies]
async-trait = { workspace = true }
serde_json = { workspace = true }
ravalink-plugin-api = { path = "../plugin-api" }
ravalink-protocol = { path = "../../protocol" }

Implémentation minimale

use async_trait::async_trait;
use ravalink_plugin_api::{
    PluginDescriptor, PluginError, PluginLoadResult,
    PluginLoadType, RavaLinkPlugin,
};

pub struct ExamplePlugin;

#[async_trait]
impl RavaLinkPlugin for ExamplePlugin {
    fn descriptor(&self) -> PluginDescriptor {
        PluginDescriptor {
            name: "example".into(),
            version: env!("CARGO_PKG_VERSION").into(),
            description: "Example source plugin".into(),
            capabilities: vec!["search".into()],
        }
    }

    fn supports_identifier(&self, id: &str) -> bool {
        id.starts_with("example:")
    }

    async fn load_tracks(
        &self,
        identifier: &str,
    ) -> Result, PluginError> {
        let query = identifier.strip_prefix("example:").unwrap_or("").trim();
        if query.is_empty() {
            return Ok(Some(PluginLoadResult::new(
                PluginLoadType::Search,
                serde_json::json!([]),
            )));
        }

        // Implement provider lookup and track conversion here.
        Ok(Some(PluginLoadResult::new(
            PluginLoadType::Search,
            serde_json::json!([]),
        )))
    }
}

Cet exemple est un squelette : il renvoie une recherche vide et ne résout aucun média. Une implémentation réelle doit produire des pistes correctement encodées, préserver les métadonnées fournisseur dans pluginInfo et fournir une source audio compatible avec le pipeline de lecture.

Enregistrer le plugin

  1. Ajoutez le crate comme dépendance de crates/server/Cargo.toml.
  2. Construisez le plugin au démarrage du serveur.
  3. Enregistrez-le via PluginRegistry::register ou register_shared.
  4. Vérifiez que les préfixes ne chevauchent pas ceux des autres sources.
  5. Ajoutez les informations de source et des tests de démarrage si l’intégration est publique.

Tests à prévoir

  • Parsing des identifiants et préfixes invalides.
  • Sérialisation des pistes, playlists et résultats de recherche.
  • Erreurs fournisseur, résultats vides, timeouts et réponses trop volumineuses.
  • Métadonnées et sélection d’une source réellement lisible.
  • Enregistrement et interaction avec les autres source managers.
cargo fmt --all -- --check
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings

Limites et sécurité

  • La découverte des plugins a lieu au démarrage : redémarrez le nœud après chaque installation ou mise à jour.
  • Les noms et préfixes doivent être uniques. youtube, lavasrc et lavasearch sont réservés.
  • Un plugin externe est un exécutable de confiance avec les mêmes permissions système et accès fichiers que RavaLink. Il n’est pas sandboxé.
  • Chaque appel externe est limité à 30 secondes, 4 Mio de réponse stdout et deux processus simultanés par plugin.
  • Le plugin doit retourner un flux audio HTTP(S) direct pris en charge par le serveur.
  • Ne placez jamais de secrets dans un manifeste public ou un dépôt Git.
Compatibilité Java : RavaLink ne charge pas les plugins Java Lavalink. Leur comportement doit être réimplémenté avec l’API Rust native ou le protocole externe.
